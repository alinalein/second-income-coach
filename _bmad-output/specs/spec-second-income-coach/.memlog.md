- (decision) Why: many people want an additional income stream but face idea paralysis (generic lists not matched to their skills/time/risk) and inconsistent follow-through (momentum breaks after a disruption, no low-friction judgment-free re-engagement path). Target users not restricted by employment status - employed, freelance, and self-employed all qualify.
- (capability) CAP-1 Structured intake: capture skills, interests, available time, risk tolerance, starting budget (mixed free-text/preselected), plus an open-ended 'what has stopped you before' question classified internally into known failure patterns (overwhelm, loses interest once routine, gets stuck with no next step, life disruption, forgets/deprioritizes). Success: a completed intake yields a stated or classified value for every field, including a classified failure pattern.
- (capability) CAP-2 Tailored idea generation: generate second-income ideas matched to the user's intake constraints rather than a generic one-size-fits-all list. Success: for a given intake, returned suggestions are plausibly explainable against the user's stated skills/time/budget/risk (reviewable, not just random selection from a fixed list).
- (capability) CAP-3 Adaptive plan and timeline generation: once an idea is selected, break it into small concrete steps with an estimated timeline, sized and sequenced according to the user's classified failure pattern; reveal only the current and immediate-next step, unlocking the following step with a short why-it-matters explanation once the current one completes. Success: a generated plan has ordered steps with timeline estimates, only current+next step is visible at any time, and step granularity differs across at least two different failure-pattern categories.
- (capability) CAP-4 Non-punitive check-in system: ongoing check-ins over voice and text; a lightweight energy/status input precedes any task ask, offering a smaller step on low-capacity days; missed check-ins are a normal reset (no streak counters, no guilt framing) and automatically shift the timeline rather than leaving it stale; a distinct acknowledgment fires when the user starts a step, separate from the acknowledgment when it's completed, and completion acknowledgment references the specific action taken rather than generic praise. Success: a missed check-in produces a recalculated timeline and a neutral re-entry message with no shame/streak language; starting and finishing a step produce two distinguishable acknowledgment messages; both voice and text check-in are exercised end-to-end at least once.
- (capability) CAP-5 Live income and opportunity projection: after each completed step or check-in, show an updated income estimate plus the concrete next opportunity it unlocks, computed from the user's actual progress and consistency rather than a one-time static guess. Success: the projection value changes between two check-ins with different actual progress, proving it is derived from live data, not fixed at intake.
- (constraint) No streak counters or escalating guilt-based nudges anywhere in the check-in system - this rules out common habit-app patterns (e.g. Duolingo-style streaks) by design.
- (constraint) Voice must be a first-class interaction channel for check-ins, not an afterthought bolted onto a text-only flow.
- (constraint) No gamified visual layer (avatar, pet, plant, points, levels) in this version - explicitly deferred to avoid diverting build time from the core agent logic for the course deadline.
- (note) Non-goal: any agent concept other than Second Income Coach is out of scope - earlier ideation explored several alternatives before converging on this one.

- (decision by user) Idea/plan lifecycle (extends CAP-2/CAP-3, warrants its own capability): of the 5 generated ideas, user selects one to work on (normal click/chat step, not HITL); the other 4 are retained as 'bookmarked', not discarded; user can mark any idea 'rejected' and it disappears from the list. Selecting an idea triggers create_plan, saved as status=draft, not active. activate_plan is the HITL step: it pauses (interrupt) and surfaces the draft in the UI for the user to confirm, modify, or reject. Confirm -> plan becomes active. Reject -> agent generates a revised draft from the feedback via create_plan again. Switching later: user can activate a different bookmarked idea's plan; the currently active plan is paused (not deleted/regenerated), so resuming it later doesn't start from scratch.
