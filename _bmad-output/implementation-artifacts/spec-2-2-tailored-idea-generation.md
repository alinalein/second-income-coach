## Intent

**Problem:** A completed intake (Story 2.1) has no idea-generation path yet — users have no way to turn their skills/time/budget/risk/failure-pattern into concrete, grounded income ideas.

**Approach:** Add an LLM-backed `generate_ideas` tool (AD-4) that reads the caller's intake row directly from Postgres, runs its own bounded, nested tool-calling step against `web_search` (the project's first MCP tool, via `@langchain/mcp-adapters`'s `MCPAdapter`, **Tavily** chosen — purpose-built for agent search grounding, one env var, simple stdio `npx` server) to source a baseline income rate per idea, moderates+caches each search result via a new `wrapToolCall` hook before it ever reaches model context, then composes exactly 5 ideas validated by a shared Zod schema and persists them atomically. A new shared `shared/money.ts` helper (minor units + currency code, configured EUR/USD rate, `Intl.NumberFormat`, estimate labeling) backs startup-cost and baseline-rate display, reused by later stories. A card-layout `web/src/features/ideas/` view renders the 5 ideas.

## Boundaries & Constraints

**Always:**
- `generate_ideas` reads intake fields directly from Postgres by `userId` (derived from `config.configurable.thread_id`, same `deriveUserIdFromThreadId`/`discovery:` prefix pattern as `submit_intake`) — never model-supplied intake data.
- `web_search` is never added to the outer agent's `tools: [...]` in `src/agent/index.ts` — it is constructed there (async, via `MCPAdapter.listTools()`) and passed as a dependency into `generate_ideas`'s own factory, which binds it to a second, stateless (uncheckpointed), bounded (max ~6 iterations) `createAgent` instance used only inside that tool's implementation. This is what makes "used only by `generate_ideas`" literally true at the code level, not just a prompt convention.
- The nested instance's `middleware` includes a new `wrapToolCall` hook (new file, e.g. `src/agent/moderation-web-search.ts`) that: screens every `web_search` result via the existing `ClassifyText`/`defaultClassify` mechanism (reused, not reimplemented) with AD-11's "strip the flagged portion" policy; and owns a short-TTL in-memory cache keyed by query, written only with the already-moderated result (cache hit skips the call entirely) — this hand-rolled cache replaces AD-7's literal `CachePolicy` because `createAgent`'s compiled graph has no per-tool `setNodeDefaults` seam (confirmed: only the outer `'model'` node in `src/agent/index.ts` has one, via `applyModelNodeResilience`).
- `generate_ideas`'s own LLM output (the 5 idea drafts) is validated against `shared/schemas/ideas.ts` before any Postgres write; a validation failure is retried or surfaced as a tool error, never saved (AD-4). All 5 rows insert in one DB transaction — never 1–4 partial rows.
- Each idea's rationale must contain the literal value/label of ≥3 different intake fields (deterministic substring check against the intake record, not a Zod rule); weekly time and risk level reuse intake's own enum tokens (`weeklyTimeAvailability`/`riskTolerance` from `shared/schemas/intake.ts`) so "never exceeds" is a same-enum-ordinal comparison; budget uses a fixed numeric ceiling per intake's budget-range bucket.
- Baseline rate + citation persist once per idea as `{ amountMinorUnits: integer, currencyCode, citation: string }` — never a float, never re-fetched after persistence (AD-6).
- `GET /api/ideas` returns raw minor-units + currency as stored, plus the caller's `userSettings.currency`; the frontend calls `shared/money.ts`'s `convertMoney`/`formatMoney` to render (so a later currency-setting change re-renders correctly without a new fetch, per AD-27).
- `replyLanguage` is a validated enum arg on `generate_ideas`'s tool schema, the model supplies it from its own reasoning — same precedent as `submit_intake`'s `failurePattern` (AD-4), not a new mechanism.
- `TAVILY_API_KEY` is required at startup (no degraded mode exists for this capability, unlike AD-20's optional registry providers).

**Never:**
- Don't touch `web/src/chat/**`, `src/api/routes/chat.ts`, `src/agent/language*`, `src/agent/resilience.ts`'s existing model-node policy, `src/agent/model.ts`, `web/src/features/settings/**`, `web/src/features/intake/**`/`submit_intake`, auth/session code, `scripts/`, `web/vite.config.ts`.
- No `excludeIds`/already-seen-exclusion field on the schema yet — that's Story 2.4's addition, not pre-built here.
- `src/api/index.ts` gets a small, necessary exception: 2–3 lines to `await` the async `MCPAdapter`-backed web-search tool construction before `createCoachAgent(...)` (not in the original file list, but `MCPAdapter.listTools()` is inherently async and `createCoachAgent` stays synchronous — same class of necessary boundary exception Story 2.1 hit with `CreateCoachAgentDeps`).

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| No intake row | User with no `intake` row calls generate | Tool errors, zero rows written | Generic error, route surfaces it |
| Happy path | Completed intake | Exactly 5 ideas inserted atomically, each citing ≥3 fields | N/A |
| Nested LLM output fails Zod | Malformed structured output | Never written; retried or surfaced as error | AD-4 |
| Idea would exceed budget/time/risk | Nested LLM drafts an over-limit idea | Deterministic post-check rejects/retries that draft before persistence | N/A |
| `web_search` result flagged | Moderation triggers on a search result | Flagged portion stripped, search not rejected whole | AD-11 |
| Repeat query within TTL | Same search query, second call | Cache hit returns prior moderated result, no new MCP call, no re-moderation | AD-7 |
| Two intakes differ ≥2 fields | Distinct intake records | Resulting idea sets differ | N/A |

## Design Notes

- Nested `createAgent` is uncheckpointed/ephemeral — constructed fresh per `generate_ideas` call, never persisted, never reachable by the outer discovery-thread agent.
- `wrapToolCall` hook exported both as the raw `(call, next) => ...` function (for direct unit testing with fakes) and `createMiddleware`-wrapped (for the nested agent's `middleware:`).
- Rationale-cites-≥3-fields and never-exceeds-limits are enforced by plain TS checks run on the nested LLM's parsed output before the transaction, not by Zod alone (Zod can't do cross-record substring/ordinal checks).
- Progress label registry (Story 1.5) is `backlog` on `main` — no label added; generic fallback applies.
